Code Server

So how are you going to code? You could just use GNU nano. That... works, but as someone who did that for a while, don't... I used it for coding until one day I was sitting in the dining center commons and working on some code with nano. My wifi randomly disconnected and I lost some progress. Since then, I've been using code server. It auto saves which is nice but it's also just better for coding. You could use a tool called micro, which I do recommend you still install as it's still useful sudo apt install micro but I say we use Code Server. If you've heard of Microslop's Visual Studio Code, this is this that but on a server. To install, simply run curl -fsSL https://code-server.dev/install.sh | sh It'll prompt you for a few things, follow them as needed. One other thing I wanna mention is by default code server uses port 8080. A lot of things use that port and I really hate it because it just causes conflict. There are 100,000 port numbers, I don't know why software keeps using the same one. Because it can cause conflict, I just recommend you rebind the port. Do that by editing the config nano ~/.config/code-server/config.yaml and you should see a few things. Look for bind-addr: 127.0.0.1:8080 and change that to whatever port you desire. You'll also need to change it to 0.0.0.0 for it to work. Mine looks like this: bind-addr: 0.0.0.0:8675 The purpose of the 0.0.0.0 is to make it you can actually access it off your server. I think you could leave it 127.0.0.1 and do a loopback, but this is just easier. While you're here, I recommend changing the password to something you'll remember. Save and exit, then run sudo systemctl enable --now code-server@$USER to start the service. Go to your LAN IP followed by the port and login via the password you changed it to. Now you're in! C

Alright! Now this is what I'm excited to talk about! C is the language I'm most familiar with and I'm creating SpyderFly in. What is C? It actually has an interesting history. Created by Dennis Ritchie at AT&T's Bell Labs in the early 70s, it was created to replace the assembly coding language UNIX was written in. Yes, the guy who created C was the co creator of UNIX along with Ken Thompson. You don't install C to run a program, you install its headers. To install it, run sudo apt install build-essential manpages-dev -y which creates headers in /usr/include/ that C uses. I'd say C is easier to learn compared to other languages, but is not nearly as simple as python. Python is middle school math, C is high school algebra, and the other languages are college calculus. So, what is C used for? It's used for operating system development and software development. Stuff like NGINX (which is what this site currently runs) was made in C. I'd love to tell you how to write C, but I am the wrong person to do that. So how should you learn it? I asked someone a while ago what book I should get and they recommended me the "bible of C programming" as it's called: C Programming: A Modern Approach Second Edition by: K. N. King. Considerded the gold standard of C books. It's a pricy book, yes, but it's worth it. I have a copy, and I love it. It doesn't feel like a book, it feels like you're sitting in a professor's class teaching. Very well written and easy to follow. However, it's mostly focused on the "portable" C. Meaning the code in the book will work on Mac, Windows, or Linux. I got The Linux Programming Interface by: Michael Kerrisk.

Assembly

Assembly is considered the oldest programming language. Not used as much today, but still taught at universities and used parts in The Linux Kernel. The first version of UNIX was made in Assembly in 1969 until a few years later the co creator Dennis Ritchie made C and rewrote UNIX in that. Assembly is not a portable language. Meaning It will not be the same on Intel as AMD or Linux as Windows. Because of its lack of portability and its general outdatedness, it's not used as much. I have no ways to recommend you learn it because it depends. Install it by running sudo apt install -y nasm build-essential

Swift

Swift is one of the reasons most developers use Mac. Swift is the language used to make apps on iOS. You can install it and compile it on Linux and Windows, but for an app, you need to compile the app on Mac. Another part of Apple's proprietary bull. To install, run:

curl -O https://download.swift.org/swiftly/linux/swiftly-$(uname -m).tar.gz && \
tar zxf swiftly-$(uname -m).tar.gz && \
./swiftly init --quiet-shell-followup && \
. "${SWIFTLY_HOME_DIR:-$HOME/.local/share/swiftly}/env.sh" && \
hash -r
You can do it on an Apple server, if I'm correct, but I'm not sure. Lemme check... Yeah, it's called Xcode Cloud.
